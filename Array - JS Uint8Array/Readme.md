# Uint8Array 是一种类型化数组（TypedArray）
在 JavaScript 中，Uint8Array 是一种类型化数组（TypedArray），用来表示一个8位无符号整数（8-bit unsigned integer）的数组
Uint8Array 数组类型表示一个 8 位无符号整型数组，创建时内容被初始化为 0。创建完后，可以以对象的方式或使用数组下标索引的方式引用数组中的元素。

# 核心特点
数据范围：每个元素占 1 个字节（8 位），取值范围是 0 到 255（例如：255 的二进制为 11111111）。
固定长度：在创建时需要指定大小或初始化数据，创建后长度固定，不能动态扩容。
默认值：除非显式提供数据，否则所有元素默认初始化为 0。
底层机制：它是对底层二进制内存块（ArrayBuffer）的一种视图，常用于处理二进制数据。

# 常见用途
文件读写与传输：处理 Blob、File、ArrayBuffer，如解析图片、音频、视频或进行文件上传/下载。
网络通信：处理 WebSocket、fetch 或 gRPC 传输的二进制数据流。
加密与编码：配合 Web Crypto API 处理哈希、签名、Base64 或十六进制转换。


# 但为什么不直接用更常见的 new Array(n) 呢？主要有以下几个核心原因：

- 1. 内存与性能开销更小（极致的性能优化）
new Array(n) 创建的是普通 JS 数组：
在 JavaScript 中，普通数组本质上是对象，它们在内存中是以键值对（哈希表）或稀疏数组的形式存在的，会有额外的内存和查找开销。
new Uint8Array(n) 创建的是底层类型化数组（TypedArray）：
它分配的是连续的原始内存空间。因为每个元素固定只占 1 个字节（8 位），所以在处理大规模数据（如 LeetCode 中  很大时）时，它的内存占用远低于普通数组，并且CPU访问连续内存的速度极快，非常适合算法题中高频的读写操作。

- 2. 默认值更符合算法需求
new Uint8Array(n) 在创建时，会自动把所有元素全部默认初始化为 0。在这道题里，0 刚好可以代表“未被标记（可能是质数）”，省去了额外使用 .fill(0) 的步骤。
如果你用 new Array(n)=>创建出来的其实是一个含有  个空位（empty slots）的稀疏数组。
⇒ 如果不手动调用 .fill(0) 或 .fill(true)，
⇒ 直接去遍历或读取里面的元素会得到 undefined，无法直接当作数字 0 或布尔值参与逻辑判断。
